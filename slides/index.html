13:31 (4 min). The difference from chat: the agent runs code on your machine and sees the results. If a model fails to converge or a variable name is wrong, it reads the error and tries again. For a reproduction this means the numbers can come from code that actually ran on the data, and we can rerun that code ourselves.

Behind the prompt

Four habits, in this prompt

Context

The paper, with its linked data and code.

"Consider the preprint at [URL] and the linked supplementary data and code"

Grounding

One script that runs from a clean start.

"one script … produces every number you report"

Plan/questions

List the alternatives and predictions before running them.

"Before running anything, list 6–10 alternative choices"

Verify

Published vs. reproduced, with the source of each number, and a list of decisions.

"say where you got it"

13:43 (5 min). The same four habits I use for any agent task. Writing predictions before running is a small pre-registration: it lets us see whether the agent expected what it then found.

What to do

The prompt asks for the source of each published number.

For real checks, use material the model cannot have memorised: your own work, or recent work like case C. Asked from memory, no agent could give its estimates.

13:51 (4 min). We asked each agent, with no files and no web, what Jung et al. found, whether it held up, and what Silberzahn et al. reported. We checked the answers against the sources. Claude and Codex declined to give coefficients ("I will not give numbers that could be wrong"). All three named all four authors of the hurricane paper (the prompt said only "Jung et al."). DeepSeek also gave volume and pages: the volume (111) was right, the pages (10185–10190; actual 8782–8787) wrong. Before 1979 all Atlantic hurricanes had female names, so name gender is confounded with era; the case A robustness slide shows all three chose that check. Case C memory probe: Opus 5.5 recalled the study design (the many-analysts immigration data, direction of the claim) but no estimates and no critique; Codex (Sol) recalled only the rough idea; DeepSeek did not know the paper. So if the published numbers come from memory, "reproduced" can mean "recalled", and the robustness checks may follow a critique the agent has read. Other options: rerun the script yourself, rename the variables, or use synthetic data with a known effect.

Case C · what the replicators found

Two agents saw the problem. None ran the check.

  • Four discipline codes each hold one team. Their fixed effects absorb 80 estimates that go against the hypothesis .
  • Merge those four codes, and the per-point effect falls from 0.011 (p = .06) to 0.001 (p = .94). The agents' pro–anti contrast falls from 0.085 (p = .008) to 0.044 (p = .23).
  • Dropping the weights, or using the original study's standardised estimates, also removes the per-point effect.
  • The authors reply that their discipline coding is a theory-driven choice .
Auspurg & Brüderl, I4R Discussion Paper 303 (June 2026): "Due to idiosyncratic variable coding, 80 data points from four research teams that contradict the ideology hypothesis were effectively excluded from the analysis. Correcting this error renders the ideology effect statistically insignificant." Their main text tests the per-point effect (Table 1, column 1), which they call B&B's preferred specification, and argues that extreme-group contrasts lose information and inflate effects. Their supplement (Section E, Table A3) reruns all nine Table 1 models with their three changes: the pro–anti contrast falls to 0.012 (p = .29), and no model stays significant even at 10%. The paper itself presents columns 1–3 as three alternative specifications and highlights the 0.085 contrast in the text, so the agents' choice of main result is defensible. The single-change numbers on the slide (merge only: pro–anti 0.085 → 0.044, p = .23; per-point 0.011 → 0.0006) are my own calculation. Borjas & Breznau's reply (DP 304) also says researcher-level models without the single-team cells stay significant in most specifications. The teaching point: seeing an oddity and testing whether it matters are different steps. The prompt asked for alternatives chosen in advance; none of the agents went back after noticing the cells.

What each agent decided without being asked

  • Trusting the documentation. The data's documentation describes one variable wrongly. Claude checked the data and noticed; Codex and DeepSeek built on the error.
  • Where "severe" starts. A median split, 1 SD above average, or the 75th percentile of damage: death ratios from ×1.5 to ×5.1 from one model.

What still needs a human

  • Deciding what counts as the "main result" before the agent does.
  • Checking where each published number came from: the paper, or memory.
  • Judging whether an alternative analysis is defensible, or only different.
  • Following up an oddity the agent reports: does it change the result?
  • Rerunning the script and reading the code, especially the data cleaning.
